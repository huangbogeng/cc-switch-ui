**配置编辑更安心，跨协议路由更可靠，升级与恢复更清楚。**

0.3.2 汇集 v0.3.1 之后的 Provider、Claude Code 用户设置、本地路由和备份改进。保存前可以预览目标与改动；遇到外部编辑时保留草稿并明确选择冲突处理方式。协议转换完善了提醒、工具结果和 Responses reasoning 的传输，也修复了目标选择失败后启动旧路由的问题。

## 配置编辑：预览、合并与冲突处理

- **只合并你修改的字段。** Provider 和 Claude Code User Settings 会保留未修改字段的外部变化。冲突时可选择 **Keep external changes** 或 **Use my changes**；取消保留草稿，确认期间再次发生变化则重新要求确认。
- **保存前查看影响。** Provider 的 **Preview save** 显示数据库/live 路径和变化字段名，不返回凭据值。用户设置的 **Preview changes** 显示两个用户字段的前后值。预览不写文件、不创建备份；保存时再次检查实际状态。
- **旧配置编辑更稳定。** 保留顶层设置、旧协议字段、认证适配器和 OAuth 账号绑定。仅改名不会把未编辑的连接字段替换成表单默认值。识别为 Codex OAuth 的导入记录会在保存时规范为 Responses，同时保留账号和原始冲突基线。

预览针对编辑器的保存操作。选择 Direct Config、切换 Route Target 和恢复备份仍是独立操作。

## 本地路由：协议与认证正确配合

- **选择失败立即中止启动。** HTTP 成功但返回 `success: false` 的目标变更会显示错误，不再继续启动之前的目标。
- **协议选择独立于认证。** `meta.apiFormat`、旧 `api_format` 和服务商默认值按顺序解析；Codex OAuth 使用专用 Responses 路径。仅声明 OAuth 模式或 Codex 绑定的导入记录也能正确识别，缺少托管账号时不会回退到 API key。
- **保留提示与工具内容。** Anthropic 原生路由保留请求结构、能力头和查询参数；Chat/Responses 转换保留运行提醒、工具结果、工具引用和支持的媒体内容。转换路径仅去掉系统文本开头的 billing attribution 行和模型 ID 的 `[1m]` 后缀。
- **Responses 状态更明确。** 支持 JSON 和 SSE 回复，区分失败、取消和预算耗尽，拒绝中途断流与无效工具参数；UTF-8 跨分包与 CRLF 事件边界得到处理。加密 reasoning 使用版本化载体和字段白名单回传，过滤仅适用于输出的字段与孤立状态。

**兼容范围：** Gemini Native 转换、托管服务端工具和 Chat 文档输入仍不支持；相关请求会明确拒绝。转换后的函数工具提前加载，工具引用保留为 JSON 文本，不等于 Anthropic 原生延迟加载。加密 reasoning 仅作不透明传输，不保证跨账号、模型或服务商可用。需要完整 Claude 原生能力时，选择 Anthropic 兼容端点。详细行为见[协议兼容说明](https://github.com/huangbogeng/cc-switch-ui/blob/v0.3.2/docs/protocol-compatibility.md)。

## 模型选择、环境诊断与备份

- **按用途选择模型。** Fetch models 打开可搜索列表，选择 Main / Haiku / Sonnet / Opus 后通过 **Apply model** 仅更新该用途的草稿。取消不修改草稿；保留未列出的已配置模型与手动输入。列表分批显示，端点或凭据变化会使缓存失效，旧响应不会覆盖新列表。
- **检查配置覆盖来源。** Settings 的 **Configuration overrides** 按需检查服务进程环境与常见 shell 文件，仅返回支持的变量名和来源，不返回值、不执行或修改 shell 文件。无法检查的来源单独显示；客户端实际环境可能不同。
- **查看备份存储范围。** Backup Center 的 **Inspect backup storage** 展示数据库、迁移、原配置、Skills 和安装升级副本的固定路径、逻辑字节数、顶层条目数及时间。缺失、不可访问和不完整扫描有明确区分；存储概览不验证备份可恢复性，也不删除备份。

Codex 新建预设使用 `gpt-6.1-sol`，已有 Provider 保留原模型设置。账号权限与模型访问由上游决定；OAuth 模式仍需手动填写模型 ID，模型发现按钮保持禁用。

## 预设调整

移除 **OrcaRouter** 的内置预设、初始数据库默认项、专用品牌资源和宣传链接。升级保留已有数据库中的 Provider 记录及凭据，需要时可按自定义 Provider 管理；不会自动删除用户配置。

## 升级到 0.3.2

Linux / macOS 发布包安装可运行：

```bash
cc-switch-ui update
cc-switch-ui version
cc-switch-ui status
```

**数据库仍为 schema 5。** v0.3.1 → v0.3.2 不新增 schema 迁移；更早版本仍会在迁移前保留原数据库快照。安装升级继续保留旧程序和完整 profile。升级前备份 `~/.cc-switch`，并单独保存重要 live 配置；回退时使用对应的旧程序与数据副本。

Linux 的新版安装脚本通过实际可执行文件识别 PATH、相对路径和别名启动的服务，并保留带空格参数；不同程序即使伪造命令名也会被拒绝。已安装的旧 updater 在升级前仍使用旧脚本逻辑。旧版没有 `update`，或 v0.3.1 updater 拒绝有效的 PATH 启动时，可使用固定版本脚本：

```bash
curl -fsSL https://raw.githubusercontent.com/huangbogeng/cc-switch-ui/v0.3.2/install.sh | bash
```

macOS 保留保守的命令路径检查。升级后检查版本、Provider、OAuth 绑定、MCP/Skills 及待恢复操作，再启动路由；随机 Admin Token 可能随重启变化。

## English highlights

This release adds field-level conflict resolution and read-only save previews for providers and Claude Code user settings. Unedited external changes, legacy configuration and OAuth bindings are retained. Failed route-target selection now stops startup, while imported Codex OAuth records use the dedicated Responses contract without API-key fallback.

Protocol adapters preserve reminders, rich tool results and opaque Responses reasoning, handle terminal failures and truncated streams, and retain UTF-8 across chunk boundaries. A role-based model picker, metadata-only environment diagnostics and backup storage overview make daily operations clearer. Unsupported native capabilities remain explicit.

OrcaRouter is removed from built-in presets and branding; existing records remain. Database schema stays at 5. Upgrade CI now covers published v0.3.1 profiles and their original updater, alongside v0.1.9/v0.2.0 migration and rollback.
